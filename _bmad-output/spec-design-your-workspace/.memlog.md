topic: design-your-workspace: visual configurator for renting a workspace setup
updated: 2026-09-29T14:15

- (direction) User input: visual builder/product configurator for renting a workspace; user chooses monitors, chair, desk and other accessories; visual changes based on selection.
- (decision) Express mode chosen by user; loose work, no initiative; slug design-your-workspace.
- (capability) CAP-1 Browse catalog by category (desk, chair, monitors, accessories) with name, visual, rental price per option.
- (capability) CAP-2 Select exactly one desk and one chair; picking another replaces the current one.
- (capability) CAP-3 Choose monitors, including more than one, and remove them.
- (capability) CAP-4 Add and remove multiple accessories.
- (capability) CAP-5 Live visual preview reflects current selection; every add/swap/remove shows immediately without reload.
- (capability) CAP-6 Itemized summary with total rental price that always matches the selection.
- (constraint) Every selectable item must have a visual representation in the preview; items without one cannot ship (core promise is the visual changes).
- (constraint) Pricing is rental (per period), not purchase; all prices and totals shown per rental period.
- (note) Non-goals: real payment/checkout, user accounts/auth, live inventory, admin catalog management.
- (assumption) Web app in a modern browser; catalog is static seed data; monthly rental period; one workspace per session; starts from an empty or default setup.
- (question) Open: stack; 2D layered vs 3D preview; rental period options; checkout/request step; compatibility rules; persist/share config; mobile support; challenge rules/deliverables; accessory list; product imagery source.
- (event) Spec derived. Pass 1 coherence: PASS — 6 caps each with intent+success, WHAT-level; 2 constraints bend design; 4 non-goals; success signal demonstrable.
- (event) Pass 2 preservation: PASS — rental, visual builder, desk/chair/monitors/accessories, visual-changes-with-selection all landed; no wrapper-only content.
- (decision) Rental priced weekly (supersedes monthly assumption); all prices and totals per week.
- (decision) Stack: Next.js; deployed to Vercel free tier -> no paid services or paid database.
- (decision) Preview is 2D layered images for now; 3D not in scope.
- (decision) Flow ends at checkout/summary; CAP-6 covers summary as checkout; no payment processing (non-goal stands).
- (constraint) Must work on phone/mobile devices as well as desktop (supersedes desktop-only assumption).
- (decision) Accessories: plants, coffee station, outdoor gear (sport, surf, motorbike), garage space; held in catalog.md companion.
- (decision) Product images are the project's own asset files, not generated or third-party.
- (assumption) Checkout confirms the rental on screen without collecting payment; details captured at checkout undecided.
- (question) Still open: compatibility rules; persist/share config; challenge rules/deliverables; checkout fields; whether image assets exist yet or placeholders needed; desk/chair/monitor option lists.
- (event) Spec re-derived with answers; companions catalog.md, stack.md. Pass 1 coherence: PASS; stack/HOW kept in stack.md.
- (event) Pass 2 preservation: PASS — weekly pricing, Next.js, Vercel free, 2D layered, checkout end, mobile, accessory list, own image assets all landed.
- (direction) User: use defaults for all remaining open questions.
- (decision) Catalog seed: 3 desks, 3 chairs, 2 monitor models, 6 accessories (plants, coffee station, sport gear, surfboard, motorbike, garage space) with sample weekly prices in USD; listed in catalog.md.
- (decision) Images: placeholder assets in the repo until the user replaces them with their own files at the same paths.
- (decision) Checkout collects name, email, start date, number of weeks; validated client-side; nothing sent or stored; total = weekly total x weeks.
- (decision) No compatibility rules; monitors capped at 3 so the layered preview has defined slots.
- (decision) Configuration persists across reload in browser storage; no share link.
- (decision) Deliverables: README (run + deploy instructions) and automated tests for selection and pricing logic; no deadline or judging criteria given.
- (event) Spec re-derived with defaults; CAP-7 added (persist on reload); open questions cleared. Pass 1 coherence: PASS. Pass 2 preservation: PASS. Spec finalized.
